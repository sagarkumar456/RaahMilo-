# TrackMyPhone — Flutter Android starter

A **consent-based** GPS app styled after the 14-screen mockup. Source code (not a prebuilt APK). Includes onboarding, email registration/login/reset, home dashboard, live GPS marker and polyline, trip history, trip detail with realtime stream, approved viewer-by-UID sharing, geofence *screen-level visualization*, notification placeholder, profile/logout.

## Before starting
- Install Flutter SDK and Android Studio, connect a real Android device with Developer Options / USB debugging.
- `flutter doctor -v` must succeed. Use a recent Flutter stable (prefer Flutter 3.29+ for geolocator 14).
- Create a Firebase project at https://console.firebase.google.com.
- In **Authentication > Sign-in method**, enable **Email/Password**.
- Create Firestore database. Paste `firebase/firestore.rules` into **Firestore Database > Rules** and **Publish**.
- Enable **Maps SDK for Android** in Google Cloud for that Firebase project, configure billing, and create a **restricted Android Maps API key** (Android package name + SHA-1). Google Maps is not necessarily free.

## Installation — new Flutter shell + source ZIP
```bash
flutter create --platforms=android --org com.yourcompany trackmyphone
cd trackmyphone
```
Copy `lib/main.dart` and `pubspec.yaml` from this ZIP into the new Flutter project. Do not overwrite the `android/` directory generated by Flutter.

```bash
flutter pub get
npm install -g firebase-tools
firebase login
dart pub global activate flutterfire_cli
flutterfire configure
```
Select your Firebase project and **Android**. This generates `lib/firebase_options.dart` (intentionally absent from the ZIP because credentials are project-specific). Run `flutterfire configure` *after* `flutter create`, using the package ID shown in `android/app/build.gradle.kts`.

Edit `android/app/src/main/AndroidManifest.xml`:
- Place these `<uses-permission>` tags directly under `<manifest>` (outside `<application>`):
```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
```
- Place inside `<application>`:
```xml
<meta-data android:name="com.google.android.geo.API_KEY" android:value="YOUR_ANDROID_MAPS_API_KEY" />
```
- Replace the placeholder with a restricted key. Never commit unrestricted keys publicly. For release builds, also authorize your release signing SHA-1.

Install and run:
```bash
flutter run
```

## Try end-to-end
1. **Phone A**: register with email/password; enable location, choose precise location; tap Start Tracking. Keep app **open and visible**. The map shows the point and growing blue route. Data uploads to Firestore.
2. **Phone B**: register/login with a **different email account**; open Profile and copy UID.
3. On Phone A, open Share Trip, enter the current Trip ID and Phone B's UID, then Grant Access.
4. On Phone B, open Profile > Shared trip, enter that Trip ID, press Open Trip ID. Live Firestore snapshots update route points. With access removed, subsequent reads are denied.
5. On Phone A press Stop Tracking. History keeps the completed trip.

## Important limits of this starter
- **Foreground-only** GPS is implemented. It is NOT a 24/7 background tracker. Screen off, OS process kills, force-stop, network outage, or battery optimization can interrupt updates. Android foreground service + visible persistent notification and Play policy review are required for reliable background tracking; background permission should only be requested if necessary and justified.
- **Geofence screen** provides tap-to-select radius and INSIDE/OUTSIDE status while open; it does not send push alerts or persist a geofence.
- **Notifications screen** is a placeholder. Push notifications, trip replay animation, advanced analytics, speed alerts, anti-abuse measures, and account deletion are not implemented.
- Route points require GPS accuracy <=100 m and generally >=5 m movement; GPS can drift, and polyline is not automatically snapped to roads.
- When no location exists, the map starts at a **fixed sample viewport**, not the user's coordinates.
- Latest positions + trip points are saved to Firestore; uploads require connectivity. Offline queue/retry is **not** a reliable feature yet. Avoid running a product release without retention limits, abuse mitigation, privacy policy, deletion/export, thorough QA and security review.
- Firestore rules limit trip reads to owner or UID-listed viewers; for production, further validate **field types and allowed changes**, use App Check/rate limiting, separate access grants, account deletion, and enforce data retention.
- Viewer IDs are Firebase UIDs, **not email addresses**. Email is only for sign-in in this starter.
- No covert tracking. Obtain informed permission and show tracking indication; viewer access is revocable by owner.

## Troubleshooting
- `firebase_options.dart not found` → run `flutterfire configure` within project.
- `CONFIGURATION_NOT_FOUND` or `ADMIN_ONLY_OPERATION` → make sure Email/Password is enabled in the *same* Firebase project selected by FlutterFire.
- Blank/gray map → check Maps SDK for Android, billing, correct Android application ID, key restriction and SHA-1.
- Firestore permission denied → deploy provided rules and check login, trip owner UID, and granted viewer UID.
- No location → turn on device Location, grant Precise permission, test outside with physical device.
- Firestore costs grow with every update. Adjust distanceFilter and retention based on usage.

## Before Google Play release
Provide truthful Data Safety declaration, privacy policy, deletion mechanism, visible consent and stop controls; limit location collection to core disclosed functions. Check Google Play background location and foreground service policies. Release signing, tests, analytics/crash reporting, and Play Console listing remain your responsibility.
